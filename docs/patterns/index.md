# YottaDots Patterns

Patterns describe reusable solutions to recurring organizational problems.

A pattern should explain:

## Context

Where does this problem occur?

## Problem

What tension or constraint exists?

## Pattern

What organizational response has proven useful?

## Guardrails

What boundaries are required?

## Signals

How do we know the pattern is working?

## Anti-patterns

What commonly goes wrong?

---

Patterns can be proposed by anyone.

Accepted patterns become part of the YottaDots knowledge base.
